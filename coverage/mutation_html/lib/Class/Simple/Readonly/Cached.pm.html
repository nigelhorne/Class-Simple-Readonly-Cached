   58: =head1 SYNOPSIS
   59: 
   60: A caching decorator for L<Class::Simple>-based (and arbitrary) objects.
   61: 
   62: It is up to the caller to maintain the cache if the object comes out of
   63: sync with the cache, for example by changing its state.
   64: 
   65:     use Class::Simple::Readonly::Cached;
   66: 
   67:     my $obj = Class::Simple->new();
   68:     $obj->val('foo');
   69:     my $cached = Class::Simple::Readonly::Cached->new(
   70:         object => $obj,
   71:         cache  => {},
   72:     );
   73: 
   74:     my $val  = $cached->val();   # calls the real object
   75:     my $val2 = $cached->val();   # served from cache
   76: 
   77:     $val = $cached->val(a => 'b');   # args form part of the cache key
   78: 
   79: Note that when the object goes out of scope (DESTROY is called), the
   80: cache is cleared automatically.
   81: 
   82: =head1 DESCRIPTION
   83: 
   84: Wraps any Perl object in a transparent caching layer.  Every method call
   85: is intercepted via AUTOLOAD; on the first call (a I<miss>) the result is
   86: stored in the cache and returned.  Subsequent identical calls (same method
   87: name, same argument list) are I<hits> and are served directly from the
   88: cache without touching the inner object.
   89: 
   90: Two cache backends are supported: a plain hash reference (fast, in-process,
   91: no expiry) and any CHI-compatible object (persistent, shared, with expiry).
   92:

  509: miss proxies the call to the inner object and stores the result.
  510:

  512: installed by C<_build_cache_accessors> at construction time, so the

  516: Three stored-value forms are mutually exclusive and exhaustive:
  517: 
  518: =over 4
  519: 
  520: =item ARRAY ref
  521:

  523: in list context, or C<$array[-1]> in scalar context.
  524: 
  525: =item C<$UNDEF_SENTINEL>
  526: 
  527: The wrapped method returned C<undef> or an empty list.  Stored as the

  535: same key in list context, the scalar cannot be adapted -- the call is

  663: =head1 LIMITATIONS
  664: 
  665: =over 4
  666: 
  667: =item B<Not safe for mutable objects>
  668: 
  669: The cache is never invalidated automatically.  If the inner object's
  670: state changes after caching, the wrapper will return stale data.  The
  671: caller must either reset the cache manually or avoid using this module
  672: with objects that mutate.
  673: 
  674: =item B<Argument serialisation is naive>
  675: 
  676: Cache keys are built by joining defined arguments with C<::>.  Two
  677: different argument lists can therefore produce the same key if an
  678: argument itself contains C<::> (e.g. C<foo('a::b', 'c')> vs
  679: C<foo('a', 'b::c')>).  Callers that pass arguments containing C<::>
  680: should use a CHI backend with a custom key serialiser.
  681: 
  682: =item B<Undefined arguments are collapsed>
  683: 
  684: Undefined values in the argument list are silently dropped from the
  685: cache key, so C<foo(undef)> and C<foo()> share a cache entry.
  686: 
  687: =item B<Scalar-then-list context mismatch is a miss>
  688: 
  689: If a method is first called in scalar context and then in list
  690: context with identical arguments, the second call is a cache miss
  691: and re-invokes the inner object.  Both results are then independently
  692: cached.
  693: 
  694: =item B<C<can('new')> returns a code reference, not a boolean>
  695: 
  696: For strict correctness C<can> returns C<\&new> for the C<'new'>
  697: method rather than the boolean C<1>.  The code reference is callable
  698: but callers who compare it with C<==> to C<1> will see a mismatch.
  699: 
  700: =item B<Does not work with L<Memoize>>
  701: 
  702: C<Memoize> intercepts at the symbol-table level and conflicts with
  703: the C<AUTOLOAD> dispatch used here.
