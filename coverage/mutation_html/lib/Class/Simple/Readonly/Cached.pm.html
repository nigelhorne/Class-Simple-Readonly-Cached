   58: =head1 SYNOPSIS
   59: 
   60: A caching decorator for L<Class::Simple>-based (and arbitrary) objects.
   61: 
   62: It is up to the caller to maintain the cache if the object comes out of
   63: sync with the cache, for example by changing its state.
   64: 
   65:     use Class::Simple::Readonly::Cached;
   66: 
   67:     my $obj = Class::Simple->new();
   68:     $obj->val('foo');
   69:     my $cached = Class::Simple::Readonly::Cached->new(
   70:         object => $obj,
   71:         cache  => {},
   72:     );
   73: 
   74:     my $val  = $cached->val();   # calls the real object
   75:     my $val2 = $cached->val();   # served from cache
   76: 
   77:     $val = $cached->val(a => 'b');   # args form part of the cache key
   78: 
   79: Note that when the object goes out of scope (DESTROY is called), the
   80: cache is cleared automatically.
   81: 
   82: =head1 DESCRIPTION
   83: 
   84: Wraps any Perl object in a transparent caching layer.  Every method call
   85: is intercepted via AUTOLOAD; on the first call (a I<miss>) the result is
   86: stored in the cache and returned.  Subsequent identical calls (same method
   87: name, same argument list) are I<hits> and are served directly from the
   88: cache without touching the inner object.
   89: 
   90: Two cache backends are supported: a plain hash reference (fast, in-process,
   91: no expiry) and any CHI-compatible object (persistent, shared, with expiry).
   92:

  506: =head2 AUTOLOAD
  507: 
  508: Not called directly.  Intercepts every method call not explicitly
  509: defined in this package, looks up the result in the cache, and on a
  510: miss proxies the call to the inner object and stores the result.
  511: 
  512: Cache lookup and storage use the pre-built C<_get>/C<_set> coderefs
  513: installed by C<_build_cache_accessors> at construction time, so the
  514: backend-type decision (HASH vs CHI) is made once -- never on each
  515: dispatch.
  516: 
  517: Three stored-value forms are mutually exclusive and exhaustive:
  518: 
  519: =over 4
  520: 
  521: =item ARRAY ref
  522: 
  523: The wrapped method previously returned a list.  Served as C<@array>
  524: in list context, or C<$array[-1]> in scalar context.
  525: 
  526: =item C<$UNDEF_SENTINEL>
  527: 
  528: The wrapped method returned C<undef> or an empty list.  Stored as the
  529: sentinel string so a cache miss (undefined value) can be distinguished
  530: from a cached C<undef>.
  531: 
  532: =item Any other defined scalar
  533:

  669: =head1 LIMITATIONS
  670: 
  671: =over 4
  672: 
  673: =item B<Not safe for mutable objects>
  674: 
  675: The cache is never invalidated automatically.  If the inner object's
  676: state changes after caching, the wrapper will return stale data.  The
  677: caller must either reset the cache manually or avoid using this module
  678: with objects that mutate.
  679: 
  680: =item B<Argument serialisation is naive>
  681: 
  682: Cache keys are built by joining defined arguments with C<::>.  Two
  683: different argument lists can therefore produce the same key if an
  684: argument itself contains C<::> (e.g. C<foo('a::b', 'c')> vs
  685: C<foo('a', 'b::c')>).  Callers that pass arguments containing C<::>
  686: should use a CHI backend with a custom key serialiser.
  687: 
  688: =item B<Undefined arguments are collapsed>
  689: 
  690: Undefined values in the argument list are silently dropped from the
  691: cache key, so C<foo(undef)> and C<foo()> share a cache entry.
  692: 
  693: =item B<Scalar-then-list context mismatch is a miss>
  694: 
  695: If a method is first called in scalar context and then in list
  696: context with identical arguments, the second call is a cache miss
  697: and re-invokes the inner object.  Both results are then independently
  698: cached.
  699: 
  700: =item B<C<can('new')> returns a code reference, not a boolean>
  701: 
  702: For strict correctness C<can> returns C<\&new> for the C<'new'>
  703: method rather than the boolean C<1>.  The code reference is callable
  704: but callers who compare it with C<==> to C<1> will see a mismatch.
  705: 
  706: =item B<Does not work with L<Memoize>>
  707: 
  708: C<Memoize> intercepts at the symbol-table level and conflicts with
  709: the C<AUTOLOAD> dispatch used here.
  710:
